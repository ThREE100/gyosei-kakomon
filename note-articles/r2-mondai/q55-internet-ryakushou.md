## 【行政書士受験生向け】令和2年度 第55問〜BCCもSSLもURLも、もっともらしい和製英語の展開に引っかかったら誤りなんです〜

**出題年度：令和2年度　第55問**

> インターネット通信で用いられる略称に関する次のア～オの記述のうち、妥当なものの組合せはどれか。
>
> ア　BCCとは、Backup Code for Clientの略称。インターネット通信を利用する場合に利用者のデータのバックアップをおこなう機能。
>
> イ　SMTPとは、Simple Mail Transfer Protocolの略称。電子メールを送信するための通信プロトコル。
>
> ウ　SSLとは、Social Service Lineの略称。インターネット上でSNSを安全に利用するための専用線。
>
> エ　HTTPとは、Hypertext Transfer Protocolの略称。Web上でホストサーバーとクライアント間で情報を送受信することを可能にする通信プロトコル。
>
> オ　URLとは、User Referencing Locationの略称。インターネット上の情報発信ユーザーの位置を特定する符号。
>
> 1　ア・イ　2　ア・オ　3　イ・エ　4　ウ・エ　5　ウ・オ

この問題は、インターネット通信でよく目にするBCC・SMTP・SSL・HTTP・URLという5つの略称について、その正式名称と機能を正しく理解しているかを問うものです。いずれの略称も日常的に見聞きするものですが、本問はその正式名称の部分を、いかにもそれらしい別の英単語の組合せにすり替えて誤りを作る、という共通のパターンで構成されています。略称の文字（アルファベット）自体は正しくても、正式名称として展開した英語の中身が事実と異なっていれば、その記述全体は誤りになる、という点を意識して読む必要があります。

### ア：BCCは「Backup Code for Client」ではなく「Blind Carbon Copy」

BCCは、正しくは「Blind Carbon Copy」の略称です。電子メールを送信する際に、他の受信者にはその宛先が表示されない形で、指定した相手にも同じメールを送る（同報送信する）ための機能を指します。

**たとえば**、複数の関係者に同じ内容のメールを送りたいが、受信者どうしがお互いのメールアドレスを知らなくてよい場合に、BCC欄に宛先を入力すると、他の受信者にはそのBCC欄の宛先が見えない形でメールが届きます。

本肢は「Backup Code for Client」の略称であり、「利用者のデータのバックアップをおこなう機能」であるとしていますが、これはBCCの正式名称にも機能にも当てはまりません。

**ここが分かりにくいポイント**：BCCという3文字のアルファベットの並び自体は正しく引用されているため、一見すると正確な説明のように見えてしまいます。しかし、その3文字が実際に何の略なのか（正式名称）が事実と異なっていれば、その記述全体が誤りになります。アルファベットの並びだけでなく、展開した正式名称の中身まで確認する必要があります。

本肢は妥当でない記述です。

### イ：SMTPは「Simple Mail Transfer Protocol」で正しい

SMTP（Simple Mail Transfer Protocol）は、電子メールを送信するための通信プロトコル（コンピュータ同士が通信するための取り決め）です。本肢は、この正式名称と機能をそのまま正しく説明したものです。

**たとえば**、メールソフトからメールを送信する際、その送信の手続にはSMTPという共通のルールが使われており、送信側と受信側のサーバーがこの共通のルールに従ってやり取りすることで、メールが正しく相手に届く仕組みになっています。

本肢は妥当な記述です。

### ウ：SSLは「Social Service Line」ではなく「Secure Sockets Layer」

SSLは、正しくは「Secure Sockets Layer」の略称です。インターネット上で送受信されるデータを暗号化し、通信の内容を第三者に読み取られたり改ざんされたりしないようにするための仕組みを指します。

**たとえば**、インターネットショッピングでクレジットカード情報を入力するページなどでは、通信が暗号化されていることを示すために、SSLの仕組みが利用されています。

本肢は「Social Service Line」の略称であり、「インターネット上でSNSを安全に利用するための専用線」であるとしていますが、これはSSLの正式名称にも機能にも当てはまりません。

**ここが分かりにくいポイント**：「Secure（安全な）」という言葉のイメージから、「SNSを安全に利用するための仕組み」という説明も、それらしく感じられてしまうかもしれません。しかし、SSLはSNSに限らず、インターネット通信全般を暗号化して安全にやり取りするための仕組みであり、「専用線」という物理的な回線を指す言葉でもありません。正式名称（Secure Sockets Layer）に立ち返って、通信を暗号化する仕組みであることを確認する必要があります。

本肢は妥当でない記述です。

### エ：HTTPは「Hypertext Transfer Protocol」で正しい

HTTP（Hypertext Transfer Protocol）は、Webサーバー（ホストサーバー）とクライアント（利用者が操作する端末側のソフトウェア）との間で、Webページなどの情報を送受信するための通信プロトコルです。本肢は、この正式名称と機能をそのまま正しく説明したものです。

**たとえば**、ブラウザでWebページのアドレスを入力してページを表示させるとき、ブラウザ（クライアント）とWebサーバー（ホストサーバー）との間では、このHTTPという共通のルールに従って情報がやり取りされています。

本肢は妥当な記述です。

### オ：URLは「User Referencing Location」ではなく「Uniform Resource Locator」

URLは、正しくは「Uniform Resource Locator」の略称です。インターネット上にあるWebページや画像といった情報資源（リソース）の場所を特定するための表記方法を指します。

**たとえば**、ブラウザのアドレス欄に表示される文字列（「https://」から始まる一連の文字列）は、インターネット上のどこにその情報があるかを示すURLです。

本肢は「User Referencing Location」の略称であり、「インターネット上の情報発信ユーザーの位置を特定する符号」であるとしていますが、これはURLの正式名称にも機能にも当てはまりません。URLが特定するのは、情報を発信する「ユーザーの位置」ではなく、Webページなどの「情報資源（リソース）の場所」です。

**ここが分かりにくいポイント**：「Location（位置）」という単語が含まれていることから、「何かの位置を特定するもの」という説明自体は間違っていないように見えます。しかし、URLが特定しているのは「発信者であるユーザーの位置」ではなく、「情報資源（Webページ等）がインターネット上のどこにあるか」という点であり、位置を特定される対象を取り違えないようにする必要があります。

本肢は妥当でない記述です。

### まとめ

- **ア（妥当でない）** BCCは「Blind Carbon Copy」の略であり、メールを他の受信者に知られずに同報送信する機能を指す。「Backup Code for Client」というデータのバックアップ機能ではない。
- **イ（妥当）** SMTPは「Simple Mail Transfer Protocol」の略で、電子メール送信用の通信プロトコルである。
- **ウ（妥当でない）** SSLは「Secure Sockets Layer」の略であり、インターネット通信を暗号化して安全にやり取りするための仕組みを指す。「Social Service Line」というSNS専用線ではない。
- **エ（妥当）** HTTPは「Hypertext Transfer Protocol」の略で、Webサーバーとクライアントの間で情報を送受信するための通信プロトコルである。
- **オ（妥当でない）** URLは「Uniform Resource Locator」の略であり、インターネット上の情報資源（Webページ等）の場所を特定するための表記方法を指す。「User Referencing Location」という発信ユーザーの位置特定符号ではない。

イ・エが妥当で、正解は選択肢3です。ア・ウ・オに共通するのは、略称のアルファベット自体は正しく引用しつつ、その正式名称だけを、いかにもそれらしい別の英単語の組合せにすり替えているという出題パターンです。正しい正式名称（Blind Carbon Copy、Secure Sockets Layer、Uniform Resource Locator）を押さえておくと、この種の記述に対して警戒しやすくなります。

**正解：イ・エの組合せ（選択肢3番）**
